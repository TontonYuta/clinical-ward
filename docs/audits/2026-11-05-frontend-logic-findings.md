# Frontend logic audit — 2026-11-05

Scope: App state/actions, CPOE composer/list/detail/advice entry, patient source/detail, FEFO/inventory adapters, coldchain transitions/catalog, debt/equipment/asset callbacks, notification adapters, settings and persistence. Existing uncommitted redesign was preserved. Browser regression writes were intercepted; no live database or actual notification provider was mutated by these tests. This is a software behavior audit, not an independent validation of clinical or legal references.

## Fixed behavior

- **P1 — Generated notifications falsely asserted facility, prescriber title, signed/national publication, doses, paid fees and visits.** `SendSmsModal.tsx` now generates all categories and insert-summary content from actual source fields through `notificationContent.ts`, retaining internal ID, source status, doctor text without guessed title, medications/doses/frequencies/routes and provided instructions. Unknown facts are labelled or omitted. A saved draft is explicitly a draft; no publication/registry URL, invented facility/brand/prescriber/department, fixed seven-day treatment period or unused subject editor remains. Repeated insertion does not duplicate the source summary. The detail caller supplies actual source status/facility/department/time. Backend `sms.py` templates use neutral source placeholders, and eSMS requires an explicit registered Brandname before contacting its provider. Root separately owns advice schema/generator/notifier corrections; no new persisted status column was introduced.

- **P1 — Administrative printouts invented facts across all eight forms.** `PrintableFormModal.tsx` previously printed fixed council names, decisions104/45/88, facility/address, meeting times, patient/drug rows, asset price, passed measurements/certification, vaccine conclusions and shift cases. All bodies now use shared draft headers, source-only tables and explicit “Chưa ghi” fields. Facility/document/date/location, parties/signatures, actual supply/return, measurements/results, verified price and conclusions are not invented. Hidden medication/equipment/asset source records are marked simulation on the printed page. Returned-vessel drafts include only returned/not-destroyed controlled records; restock retains all qualifying rows without claiming physical supply; coldchain uses actual passed state/logs/batches with the recorded aggregate labelled unreconciled; shift uses open source items. Unverified legal-form/council/decision claims were removed. Eight legacy IDs, source selection, A4 printing and HTML export remain. A real PDF check also exposed the floating AI launcher leaking into print; a scoped document-isolation/wrapping rule now excludes application controls.
- **P1 — Existing FEFO operations became unreachable and held batches looked clear.** `FefoInventoryTab` now passes role-gated row/card dispatch actions and header restock entry. Held/expired/unknown/no-stock batches show blocking reasons; held actions are disabled on desktop/mobile. Pharmacist/director choose an explicitly entered positive integer quantity; the blank composer supports cancellation and only proceeds to existing authentication. Doctor/nurse stay read-only. `RestockProposalModal` no longer invents names/document numbers or uses a fake approval timer/success chime; it proceeds to authentication and leaves stock unchanged. Dispatch requests contain quantity only, with no invented dispatcher/authentication metadata.

- **P1 — Authentication bootstrap bypassed the server.** `src/main.tsx` had rendered App directly while AuthGate was commented out, so an AUTH_REQUIRED deployment could not use its login flow and retained demo roles. The entry point now mounts AuthGate and passes the server account/role/logout into App. A checking screen prevents a login flash; only explicit server-disabled authentication opens demo mode. Session401/403 opens login;503, malformed data, unknown roles and timeouts keep all clinical views unmounted and offer retry. Login/logout clear clinical caches, authenticated roles do not expose the demo chooser, and the clinical confirmation modal cannot switch App's authenticated role. Five browser regression cases exercise the real entry point.

- **P1 — CPOE assistant permission and false success.** `src/App.tsx`, `EXECUTE_CREATE_CPOE_ORDER`: enforce doctor role, validate the draft, discard assistant-provided signatures, save an unsigned draft, await server acceptance and broadcast the server-returned ID. Invalid/rejected operations create no local prescription or success. Duplicate in-flight submissions are guarded. Cards currently render no UI, so this callback issue was latent.
- **P1 — Patient identity leakage in the composer.** `src/components/RightPane/Tabs/CPOE/CpoeOrderModal.tsx`: changing patient/name clears linked ID/CCCD/DOB/contacts and other patient fields; closing unmounts the composer so a new session starts empty. Patient selection no longer invents an encounter diagnosis/ICD from chronic-condition text.
- **P1 — Route/unit corruption.** The composer previously changed Salbutamol's `Khí dung qua mặt nạ` route to intravenous injection, `Đường uống` could also become intravenous, and `Gói` became `Ống`. It now preserves the selected route/unit and displays nonstandard catalog options. API payload also forwards entered weight and insurance ID.
- **P1 — Authoritative clinical sources.** `src/services/patientService.ts` accepts successful `[]`, clears its cache on 401/403 and fails without restoring cached/example people on other errors. App initializes the patient registry empty and visibly reports unavailable data. App passes the fetched array through Dashboard to CPOE composer, prescription detail, patient detail and advice recipients; none of those active paths falls back to `INITIAL_PATIENTS`.
- **P1 — Invented CPOE identity/diagnosis/doctor.** CPOE normalization discards records without a stable prescription ID and retains unknown identity, diagnosis and doctor fields as empty. It no longer generates an RX ID, BN-0000, R69, a treatment diagnosis or a named doctor. List/cards display unknown fields explicitly. Initial prescription state no longer resurrects example prescriptions; successful server `[]` and singleton lists replace cache contents.
- **P1 — Wrong advice recipient and same-name joins.** Advice-opening events must identify an existing prescription; missing IDs no longer select the first example order. Patient detail matches an explicit patient ID first; only an unlinked prescription may fall back to a unique exact name. Reopening and order-creation events refresh the displayed record list. Debt matching follows the same identity preference.
- **P1 — Invented inventory and missing dispatch persistence.** `src/services/api/inventoryApi.ts` maps only successful server rows, including `[]`; it no longer appends missing fixture batches or enriches clinical/product identity from loose fixture-name prefixes. App starts inventory empty and displays an unavailable notice on failure. Dispatch validates positive integer amount, stock, expiry, quarantine and explicit server hold; it awaits the API and updates stock/low-stock status/audit/cache only after acceptance, propagating rejection back to the authentication dialog.
- **P1 — Restock manufactured physical stock.** Restock now submits `/inventory/restock-proposal`, waits for acceptance and leaves on-hand stock unchanged. Failed proposals do not create a local success audit.
- **P1 — Coldchain state was local and reset on reload.** `src/services/api/coldchainApi.ts` loads persisted status; simulate/restore/release perform the server operation and refetch status. Role/transition guards remain in front of actions; VVM/MKT confirmation comes from the recorded state. Failed writes leave the old state. Successful transitions also refresh inventory holds; if refresh fails, coldstock is held pending inspection. Unknown/unavailable telemetry is displayed as unknown, with an unavailable-state notice.
- **P1 — Fictional coldstock catalog and safety conclusions.** `ColdChainTab.tsx` now renders actual InventoryBatch quantities and explicit backend cabinet links/holds, rather than fifteen fixture vaccines. Unlinked batches say their cabinet association is unconfirmed. VVM/freeze/light metadata is explicitly unavailable, and missing humidity is unknown rather than 54%. Quarantine banner no longer asserts fixed VVM1/MKT5.6/12-minute safety. Backend legacy cabinet aggregate1250 is not claimed to equal linkedstock200 or converted between units; operation messages refer to linked batches.
- **P1 — Alarm acknowledged before authorization.** ColdChainTab no longer stops alarm audio or plays a success chime merely when opening restore authentication. App stops audio after accepted restore.
- **P2 — Fake local audit verification.** App begins with an empty session log and no longer imports fixture audit rows or creates SHA256-looking strings. New local entries use `session_simulated`, no integrity hash, and explicit session/simulation wording. Audit modal says these entries do not replace server audit or verified signatures.
- **P2 — Unsupported form type could crash render.** App checks runtime form keys using an own-property whitelist before both direct and assistant form openings, rejecting invalid values including `__proto__`/`constructor`.
- **P2 — AI signature status was misleading.** `AiPrescriptionAuditView.tsx` displays `Chưa xác minh chữ ký` for false verification, rather than asserting the doctor has not signed. A signature blob by itself is not verified proof.
- **P2 — Clinical notes persistence.** Root-owned parallel work added clinicalNotes to the frontend adapter and backend schema/model path. This is no longer listed as an open frontend omission.

## Remaining findings and operational limits

1. **P1, latent debt settlement can consume the wrong product and is not durable.** `src/App.tsx:474`, `handleSettleDebt`, changes only React state. Its substring matching treats `adrenalin` as matching noradrenalin and explicitly allows diazepam to match midazolam; generic infusion supplies also match different products. It selects one earliest-expiry batch without checking quarantine, expiry, sufficient stock or already-settled status, clamps stock to zero, then reports the whole amount issued. Fix before enabling this workflow: one server transaction using explicit debt/product/batch identities, open-debt and availability checks, and authoritative returned debt/stock. The debt tab and action cards are currently hidden.

2. **P1, latent borrow/return/incident/destruction callbacks still report local success independently of persistence.** `src/App.tsx:645`, `handleAddNewDebt`, inserts a local timestamp ID/code and discards the server-created debt response. Returning that local ID can 404 while the UI reports success. Assistant borrow/incident callbacks also insert locally before persistence; manual incident (`:704`) and ampoule destruction (`:783`) do not invoke their existing APIs. Fix: persist first, adopt server identity and show rejection without changing status/audit. These modules are hidden/demo workflows, not a working durable ledger.

3. **P1, latent assistant confirmation/state bypasses.** The restock card marks itself executed when opening auth; return/settlement branches (`src/App.tsx:1485`, `:1502`) additionally append success before confirmation, even if canceled. `handleSendMessage` (`:1577`) applies FEFO quantities directly to local stock and marks every outstanding narcotic ampoule returned for an `AMPOULE_RETURNED` payload. Fix before re-enabling cards: require a specific authorized confirmed transaction and mark its originating card only after completion. `ActionCardDispatcher.tsx` currently returns null.

4. **P2, latent asset transfer changes readiness and is not durable.** `src/App.tsx:1010` unconditionally sets transferred assets to `condition: operational` at `:1033`, even if previously broken/unrepairable. Asset/equipment transitions and liquidation remain local, and reload restores fixture state. Fix: preserve condition during transfer; require a separate inspection transition and adopt asset/equipment API responses. Equipment/asset tabs remain hidden.

5. **Coldchain monitoring limits.** Explicit batch↔cabinet mapping is administrative data from the backend; no mapping is inferred from a product name. Missing mapping remains an unresolved hold. Per-lot VVM/freeze/light metadata has no authoritative source and is not asserted. There is no polling/subscription for another operator's later updates; status refresh happens on mount and local transitions. The cabinet's persisted aggregate is recorded separately and is not inventory reconciliation.

6. **Clinical identity and signature limits.** Display profiles/clinical PINs in demo mode are simulation metadata, and local audit is deliberately session-only. A deployment needing authenticated clinician names/certificates and durable signatures must obtain those from an authoritative identity/signature provider. This audit does not claim the hidden legacy modules are production complete.
