PHẦN 1: TỔNG QUAN KIẾN TRÚC & TRIẾT LÝ THIẾT KẾ

1.1. Triết lý thiết kế cốt lõi (Core Architectural Philosophy)

Hệ thống được thiết kế dựa trên nguyên tắc vàng: "Nghiệp vụ lâm sàng cốt lõi phải hoạt động toàn vẹn, độc lập 100% trước khi có sự xuất hiện của AI". Trợ lý AI Copilot chỉ đóng vai trò là một giao diện tương tác phụ trợ thông minh (Decoupled Auxiliary Copilot), giao tiếp với Backend qua RESTful API tiêu chuẩn mà không bao giờ được phép trực tiếp ghi đè hay can thiệp vào cơ sở dữ liệu nếu thiếu sự xác thực của nhân viên y tế có thẩm quyền.

PHẦN 3: CHI TIẾT KIẾN TRÚC FRONTEND (CLIENT LAYER)

3.1. Công nghệ Frontend chủ đạo

  • Vite 6: Công cụ đóng gói hiện đại, tốc độ khởi động Hot Module Replacement (HMR) tính bằng mili-giây.
  • React 19 + TypeScript: Phiên bản mới nhất của React với hiệu năng kết xuất tối ưu, hệ thống kiểu tĩnh TypeScript loại trừ 100% lỗi runtime undefined.
  • Tailwind CSS v4: Hệ thống Utility-first CSS thế hệ mới, tối ưu hóa kích thước file CSS < 35KB sau khi biên dịch.
  • Lucide React: Bộ biểu tượng đồ họa vector SVG chuyên nghiệp, đồng bộ phong cách thiết kế phẳng hiện đại.

PHẦN 4: CHI TIẾT KIẾN TRÚC BACKEND & CƠ SỞ DỮ LIỆU

4.1. Lựa chọn công nghệ Backend

Backend được xây dựng hoàn toàn bằng Python 3.12 + FastAPI + SQLAlchemy 2.0 (Async/Await) + SQLite / PostgreSQL. Lựa chọn này đem lại 3 ưu thế vượt trội:

  • Hiệu năng xử lý bất đồng bộ (High-concurrency Asynchronous I/O): FastAPI kết hợp máy chủ ASGI uvicorn cho khả năng xử lý hàng chục nghìn yêu cầu/giây với độ trễ cực thấp.
  • Tự động sinh tài liệu chuẩn hóa OpenAPI 3.0 / Swagger UI: Mọi endpoint, tham số đầu vào và kiểu dữ liệu trả về đều được tài liệu hóa tự động tại đường dẫn /docs.
  • Sẵn sàng tích hợp động cơ tính toán y sinh & LLMs: Hệ sinh thái Python cho phép dễ dàng tích hợp các thư viện tính toán khoa học (tính chỉ số Arrhenius MKT) và các SDK AI tiên tiến nhất (Gemini API, LangChain).

4.3. Đặc tả các Bảng dữ liệu chính (Core Tables Specification)

  • users: Quản lý danh mục cán bộ y tế bệnh viện.
    Các trường: id (UUID), username, full_name, role (nurse|bme|pharmacist|doctor|director), practice_certificate (Số CCHN), pin_hash, rfid_card_uid, department_id.
  • debt_tickets: Sổ theo dõi mượn thuốc khẩn ca đêm (Thông tư 22 & Thông tư 20).
    Các trường: id, ticket_code (PN-2026-xxx), item_id, quantity, patient_name, patient_room, borrower_id, is_narcotic (Boolean), ampoule_status (NONE|PENDING|RETURNED|DESTROYED), status (DEBT|SETTLED), due_date (07:00 AM), settled_at.
  • equipment: Danh mục trang thiết bị y tế bệnh viện (Nghị định 98).
    Các trường: id, asset_code, model, serial_number, manufacturer, risk_level (A|B|C|D), status (READY|IN_USE|BROKEN|UNDER_MAINTENANCE), calibration_expiry_date, current_department_id.
  • inventory_batches: Danh mục các lô thuốc và hạn dùng FEFO (Thông tư 36 GSP).
    Các trường: id, item_id, batch_number, expiry_date, current_stock, min_threshold, max_threshold, is_quarantined (Boolean).
  • audit_ledger: Sổ nhật ký kiểm toán bất biến chuỗi băm (Nghị định 130 & FDA 21 CFR Part 11).
    Các trường: id, event_id, timestamp, action_type, signer_id, signer_certificate, witness_id, payload_json, previous_hash, record_hash (HMAC-SHA256).

PHẦN 5: ĐẶC TẢ HỆ THỐNG RESTFUL API ENDPOINTS

Tất cả các endpoint đều hỗ trợ định dạng JSON, phân quyền theo JWT Bearer Token và trả về mã lỗi HTTP chuẩn mực:

Phương thức Đường dẫn Endpoint Mô tả chức năng nghiệp vụ Quyền hạn & Ràng buộc bảo mật
POST /api/v1/debts/borrow Tạo phiếu mượn khẩn thuốc/vật tư ca đêm. Nurse, Director. Yêu cầu xác thực PIN. Nếu là thuốc gây nghiện, đặt ampoule_status = PENDING.
GET /api/v1/debts Truy vấn danh sách nợ cơ số tủ trực. Tất cả vai trò. Hỗ trợ tham số lọc: status, is_narcotic, search.
PUT /api/v1/debts/{id}/return-ampoule Xác nhận thu hồi vỏ ống Morphin vào khay. Nurse, Pharmacist. Bắt buộc thực hiện trước khi được hoàn bù theo Đ15 TT20.
PUT /api/v1/debts/{id}/settle Ký duyệt hoàn bù cơ số tủ trực. Pharmacist, Director. Chặn lỗi 409 Conflict nếu là thuốc gây nghiện mà chưa có vỏ ống rỗng.
POST /api/v1/equipment/incidents Báo hỏng TBYT và gắn cờ cảnh báo đỏ LOTO. Nurse, Doctor. Thiết bị loại D tự động kích hoạt mức ưu tiên Khẩn cấp (Urgent).
PUT /api/v1/equipment/incidents/{id}/handover Nghiệm thu an toàn điện và bàn giao 2 bên. BME Engineer (chủ trì) + Clinical Staff (ký nhận). Ghi sổ lý lịch máy.
GET /api/v1/inventory/batches Tra cứu kho dược sắp xếp theo hạn dùng FEFO. Tất cả vai trò. Tự động gắn cờ cảnh báo cận hạn theo 3 mức màu.
POST /api/v1/inventory/restock-proposal Lập phiếu dự trù cung ứng thuốc Mẫu 01/TT22. Pharmacist, Director. Tự động tính: Bù = Max - Tồn kho.
POST /api/v1/coldchain/telemetry Tiếp nhận dữ liệu nhiệt độ từ Datalogger IoT. IoT Device, Backend Worker. Nếu > 8.0°C kích hoạt báo động.
POST /api/v1/coldchain/release-quarantine Ký lệnh giải phóng lô vắc xin sau sự cố nhiệt độ. Director (ký duyệt chính) + Pharmacist (thẩm định MKT & VVM).
GET /api/v1/audit/verify-integrity Quét và kiểm tra tính toàn vẹn chuỗi băm HMAC. Director, Đoàn Thanh tra Bộ Y tế. Phát hiện mọi hành vi can thiệp CSDL.

PHẦN 8: QUY TRÌNH BUILD & TRIỂN KHAI THỰC TẾ (DEPLOYMENT)

8.1. Triển khai đám mây Production trên Vercel

Phiên bản Production của ứng dụng Frontend đã được đóng gói và triển khai thành công tại địa chỉ chính thức:

Đường dẫn ứng dụng trực tuyến:
URL: https://clinical-ward.vercel.app
Đã tắt hoàn toàn chế độ Vercel Authentication / SSO Protection. Bất kỳ ai (Hướng dẫn viên, Hội đồng giám khảo) đều có thể truy cập trực tiếp ngay lập tức mà không cần tài khoản Vercel.

Cấu hình định tuyến Single Page Application tại file vercel.json:

{
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}

8.2. Đóng gói Container Backend FastAPI với Docker

Khi đưa vào vận hành thực tế tại hạ tầng máy chủ bệnh viện, Backend được đóng gói qua Dockerfile tối ưu:

FROM python:3.12-slim
WORKDIR /app
COPY backend/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY backend/ .
EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "4"]
